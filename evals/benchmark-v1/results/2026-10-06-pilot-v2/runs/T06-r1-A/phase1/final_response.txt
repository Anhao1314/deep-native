## Investigation

`boltons/iterutils.py:1364` — inside `get_path`'s lookup loop, every segment was resolved against the outer `root` rather than the value reached so far:

```python
cur = root[seg]
```

So `get_path({'a': {'b': 7}}, ('a', 'b'))` first set `cur = {'b': 7}`, then looked `root['b']` again — raising `PathAccessError` when absent, or silently returning the wrong (outer) value when a same-named key existed at the root. The int-coercion fallback for list indices already used `cur`, and the docstring/doctest already described correct nested traversal, confirming this was the defect.

## Fix

`boltons/iterutils.py:1364` → `cur = cur[seg]`. This walks each segment against the intermediate value while leaving the `TypeError` fallback (string → int coercion for dotted list indices), `default` short-circuit, and `PathAccessError(exc, seg, path)` construction untouched. The docstring already documents the correct behavior, so no doc changes were needed.
