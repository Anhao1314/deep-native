## Result

**Root cause** — `boltons/iterutils.py:1364`, in `get_path`:

```python
for seg in path:
    try:
        cur = root[seg]   # looked up every segment on the ORIGINAL root
```

The cursor `cur` was assigned for each segment but the lookup always indexed `root`, so any path deeper than one level re-resolved later segments against the outer object. Nested-only keys raised `PathAccessError` (e.g. `get_path({'a':{'b':7}}, ('a','b'))` failed with `KeyError('b')`), and paths where a name existed both at the outer root and nested silently returned the wrong value. The `TypeError` fallback branch below it already used `cur`, confirming the intended pattern.

**Fix** — one token: `cur = root[seg]` → `cur = cur[seg]`. No other logic touched, so the `TypeError` retry (numeric-string segments on lists), dotted-string splitting, defaults, and `PathAccessError(exc, seg, path)` construction are unchanged.

**Regression tests added** — `agent_tests/test_get_path.py` (18 tests, unittest-discoverable): deeply nested mappings, a key repeated at the outer root (proves nested value wins), a segment only reachable through the nested mapping, mixed mapping/list nesting, tuple containers, list-of-lists, dotted nested paths, dotted list indices at multiple depths, defaults on missing/out-of-range nested segments and defaults *not* masking falsy values, plus `PathAccessError` detail checks (`seg`, `path`, underlying `exc`, `repr`/`str`, multiple inheritance).
