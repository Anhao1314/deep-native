## Summary

**Root cause** — `boltons/iterutils.py:1364`: `get_path` looked up every path segment on the outer `root` (`cur = root[seg]`) instead of on the value reached by the preceding segments. So on nested mappings, segment 2+ was resolved against the top-level object: multi-segment paths either raised `PathAccessError` or, worse, silently returned an unrelated top-level value when the later segment happened to exist at the root.

**Fix (one line)** — `boltons/iterutils.py:1364`: `cur = root[seg]` → `cur = cur[seg]`. The `TypeError` fallback already used `cur`, which still holds the previous value because the failed assignment never lands, so dotted list-index handling (`'a.b.0'`), tuple paths, defaults, and `PathAccessError` (`exc`/`seg`/`path`) semantics are untouched. The docstring's example (`get_path(root, ('a','b','c',2,0)) == 3`) now holds; `docs/iterutils.rst` autodocs the function, so no doc edits were needed.

**Regression tests** — new `agent_tests/test_get_path_regression.py` (21 tests) plus `agent_tests/conftest.py` (repo root on `sys.path`). They cover: nested mapping lookup via tuple and dotted paths, the sharp outer-root traps (`{'a': {}, 'b': 1}`, `{'a': ['x'], 1: 'top-level'}`), nested string indices, tuple roots, dotted list indices, defaults (used on failure, ignored on success), and `PathAccessError` details (`exc`, `seg`, `path`, message, catchability as `KeyError`/`IndexError`/`TypeError`).
