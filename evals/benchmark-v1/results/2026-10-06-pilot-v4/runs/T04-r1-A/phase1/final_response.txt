## Implementation — `boltons/strutils.py`

Rewrote `parse_int_list` (boltons/strutils.py:886) to parse each token with full-match validation:

- **Signed integers**: `[+-]?[0-9]+` tokens, so `-3` → `[-3]` and `+2` → `[2]`.
- **Signed inclusive ranges**: the range delimiter is matched literally (`re.escape`) between two optionally signed endpoints, so `-3--1` → `[-3, -2, -1]` and `+2-+4` → `[2, 3, 4]` parse unambiguously (signs are never mistaken for delimiters).
- **Reversed endpoints**: `min`/`max` semantics preserved (`8-5` → `[5,6,7,8]`, `-1--3` → `[-3,-2,-1]`).
- **Whitespace**: stripped around tokens and allowed around range delimiters/endpoints (`' 8 - 5 , -3 - -1 '` → `[-3,-2,-1,5,6,7,8]`).
- **Preserved behavior**: output sorted, duplicates kept, empty segments/whitespace-only input → `[]`, and custom `delim`/`range_delim` still work as *literals* (regex-special delimiters like `.`, `*`, `+` are escaped; multi-char delimiters work).
- **Malformed input raises `ValueError`**: tokens like `1-2-3`, `1--2--3`, `1-`, `--1`, `a`, `+ 1` now raise instead of being silently accepted/rejected differently.

Docstring updated with signed/range semantics, whitespace and reversed-range notes, a `Returns`/`Raises` section, and new doctest examples.
